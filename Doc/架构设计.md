# NewLife.Siemens 架构设计

## 1. 架构概览

NewLife.Siemens 采用**五层分层架构**，从网络传输到业务驱动，每层职责单一，向上屏蔽细节：

```
┌─────────────────────────────────────────────────────────────────┐
│                     Layer 5：IoT 驱动层                          │
│  SiemensS7Driver（DriverBase）   SiemensParameter   SiemensNode  │
│  与 NewLife.IoT 标准接口对接，多节点共享连接，统一点位读写        │
└───────────────────────────┬─────────────────────────────────────┘
                            │ 使用 S7Client
┌───────────────────────────▼─────────────────────────────────────┐
│                     Layer 4：S7 客户端层                         │
│   S7Client（核心 API）                                           │
│   OpenAsync / Close / ReadBytes / WriteBytes / InvokeAsync       │
│   协调 S7Message / COTP / TPKT 序列化，处理 PDU 分段与序列号     │
└─────────┬──────────────────────────┬────────────────────────────┘
          │                          │
┌─────────▼──────────┐   ┌───────────▼────────────────────────────┐
│  Layer 3：消息层    │   │         Layer 2：COTP 传输层            │
│  S7Message         │   │  COTP（CR/CC/DT 帧）                    │
│  S7Parameter       │   │  COTPParameter / COTPParameterKinds     │
│  SetupMessage      │   │  TsapAddress（TSAP地址对）              │
│  ReadRequest/Resp  │   │  DataItemAddress                        │
│  WriteRequest/Resp │   └──────────────────┬──────────────────────┘
│  RequestItem       │                      │
│  DataItem          │            ┌─────────▼──────────────────────┐
└────────────────────┘            │     Layer 1：TPKT 传输层       │
                                  │  TPKT（ISO on TCP 4字节头）    │
                                  │  TPKTCodec（流式粘包处理）     │
                                  └──────────────────┬─────────────┘
                                                     │
                                           TCP Socket（端口 102）
```

### 数据流（读操作示例）

```
用户调用 ReadBytes("DB1.DBW0", 2)
    → PLCAddress 解析地址 → DataType=DataBlock, DB=1, StartByte=0, VarType=Word
    → BuildRead → 构造 RequestItem（SyntaxId=0x10, Area=DataBlock, DbNumber=1, Address=0）
    → ReadRequest.ToS7Message() → S7Message(Job, ReadVar)
    → S7Message.ToCOTP() → COTP(DT 帧, Data=S7字节流)
    → COTP.ToPacket(withTPKT=true) → TPKT(4字节头) + COTP字节流
    → stream.WriteAsync(buf) → TCP 发送

    ← stream.ReadExactAsync → TPKT 头部(4字节)
    ← COTP.ReadAsync → DT 帧(读取剩余字节)
    ← S7Message.Read → AckData(ReadResponse)
    ← ReadResponse.Items[0].Data → byte[]
    → 返回给调用方
```

## 2. 协议栈详解

### 2.1 TPKT（Layer 1）

ISO Transport Protocol on TCP（RFC 1006），标准端口 102。每帧固定 4 字节头：

```
┌──────┬──────┬──────────┬──────────┐
│ 0x03 │ 0x00 │ LengthHi │ LengthLo │  ← 4 字节 TPKT 头
└──────┴──────┴──────────┴──────────┘
│  v3  │ Rsvd │    Total Frame Length (包含这4字节)    │
```

**关键类**：
- `TPKT`：头部解析（ReadHeader/WriteHeader）和完整帧读写（Read/ToPacket）
- `TPKTCodec`：流粘包处理，从 TCP 流精确读取完整 TPKT 帧

### 2.2 COTP（Layer 2）

Connection-Oriented Transport Protocol（ISO 8073 / RFC 905）。

**帧类型（PduType）**：

| 类型 | 值 | 用途 | 关键字段 |
|------|-----|------|---------|
| `ConnectionRequest` (CR) | 0xE0 | 发起连接 | Destination, Source, Parameters（SrcTsap, DstTsap, TpduSize） |
| `ConnectionConfirmed` (CC) | 0xD0 | 确认连接 | 同上 |
| `Data` (DT) | 0xF0 | 数据传输 | Number, LastDataUnit, Data |

**TSAP 计算规则**（`TsapAddress.GetDefaultTsapPair`）：

| CPU 类型 | 本地 TSAP | 远程 TSAP |
|---------|----------|----------|
| S7-200 | 0x1000 | 0x1001 |
| Logo0BA8 | 0x0100 | 0x0102 |
| S7-200 Smart | 0x1000 | `0x03<<8 \| (rack<<5 \| slot)` |
| S7-300/400/1200/1500 | 0x0100 | `0x03<<8 \| (rack<<5 \| slot)` |

### 2.3 S7 消息层（Layer 3）

S7 应用层协议报文头（10～12 字节）：

```
┌────────┬────────┬────────────┬────────────┬────────────┬──────────────┐
│ 0x32   │  Kind  │ Reserved   │ Sequence   │ ParamLen   │ DataLen      │
│ 1 byte │ 1 byte │ 2 bytes    │ 2 bytes LE │ 2 bytes BE │ 2 bytes BE   │
└────────┴────────┴────────────┴────────────┴────────────┴──────────────┘
 （AckData 额外附 ErrorClass + ErrorCode 各 1 字节）
```

**消息类型（S7Kinds）**：

| 值 | 名称 | 方向 | 说明 |
|-----|------|------|------|
| 0x01 | Job | 主站→从站 | 请求命令（读、写、Setup） |
| 0x02 | Ack | 从站→主站 | 简单确认（无参数，无数据） |
| 0x03 | AckData | 从站→主站 | 带数据的响应（读写响应） |
| 0x07 | UserData | 双向 | 扩展功能（诊断、SZL、时钟等） |

**功能码（S7Functions）**：

| 值 | 名称 | 说明 |
|-----|------|------|
| 0xF0 | Setup | 连接参数协商（PDU大小、AMQ） |
| 0x04 | ReadVar | 读取变量 |
| 0x05 | WriteVar | 写入变量 |

### 2.4 RequestItem 地址结构

RequestItem 是 ReadRequest/WriteRequest 中单个变量的地址描述（12 字节）：

```
┌──────────┬──────────────┬──────────┬────────────┬───────┬──────────────┐
│ SpecType │ TransportSize│  Count   │  DbNumber  │ Area  │ Address(3B)  │
│  0x12    │  1=Bit,2=Byte│ 2 bytes  │  2 bytes   │ 1byte │  3 bytes BE  │
└──────────┴──────────────┴──────────┴────────────┴───────┴──────────────┘
Address 字段为位地址（StartByte * 8 + BitOffset），3字节大端存储
```

**Area（DataType）映射**：

| 枚举值 | 协议字节 | 说明 |
|--------|---------|------|
| Input | 0x81 | 数字/模拟量输入映像区 |
| Output | 0x82 | 数字/模拟量输出映像区 |
| Memory | 0x83 | 标志寄存器（Merker）区 |
| DataBlock | 0x84 | 数据块 DB |
| Counter | 0x1C | 计数器 C |
| Timer | 0x1D | 定时器 T |

## 3. 数据模型

### 3.1 PLCAddress 地址解析

`PLCAddress(string address)` 构造时触发 `Parse()`，支持以下格式：

**数据块（DB）**：

| 地址格式 | DataType | VarType | 示例 |
|---------|---------|---------|------|
| `DBn.DBBx` | DataBlock | Byte | `DB1.DBB0` |
| `DBn.DBWx` | DataBlock | Word | `DB1.DBW10` |
| `DBn.DBDx` | DataBlock | DWord | `DB1.DBD20` |
| `DBn.DBXx.b` | DataBlock | Bit | `DB1.DBX0.0`（b=0~7） |
| `DBn.STRINGx.len` | DataBlock | String | `DB1.STRING0.60` |

**输入区（I/E）**：

| 地址格式 | 说明 |
|---------|------|
| `IBx` / `EBx` | 字节 |
| `IWx` / `EWx` | 字 |
| `IDx` / `EDx` | 双字 |
| `Ix.b` / `Ex.b` | 位（单字节+点+位号） |

**输出区（Q/A）**：同输入区格式，前缀替换为 Q/A

**标志区（M）**：前缀 MB/MW/MD/M（位：Mx.b）

**定时器 / 计数器**：`Tx` / `Cx`（x 为编号）

### 3.2 VarType ↔ .NET 类型映射

| VarType | S7 数据类型 | .NET 类型 | 字节数 |
|---------|------------|---------|--------|
| Bit | BOOL | Boolean | 1 (bit) |
| Byte | BYTE | Byte | 1 |
| Word | WORD | UInt16 | 2 |
| DWord | DWORD | UInt32 | 4 |
| Int | INT | Int16 | 2 |
| DInt | DINT | Int32 | 4 |
| Real | REAL | Single | 4 |
| LReal | LREAL | Double | 8 |
| String | STRING | String | 2+n |
| S7String | STRING | String | 2+n（S7特定格式） |
| S7WString | WSTRING | String | 4+2n |
| DateTime | DATE_AND_TIME | DateTime | 8 |
| Timer | TIMER | UInt16 | 2 |
| Counter | COUNTER | UInt16 | 2 |

> **S7 String 格式**：第1字节=最大长度，第2字节=实际长度，后跟字符数据（ASCII/Latin-1编码）

### 3.3 字节序

S7 协议使用**大端字节序（Big-Endian）**。驱动层负责与 .NET（小端）的转换：
- 读取时：`buf.Swap(true, true)` 或手动 `BitConverter.ToInt16(buf.Reverse()...)`
- 写入时：需将 .NET 值先转为大端再写入

## 5. 技术选型

| 领域 | 选型 | 理由 |
|------|------|------|
| 网络传输 | `TcpClient` + `NetworkStream` | 简单直接，避免引入额外依赖；KeepAlive 通过 Socket 选项配置 |
| 二进制解析 | `NewLife.Buffers.SpanReader` / `NewLife.Serialization.Binary` | NewLife 内置，零分配，避免手动偏移计算 |
| 数据包抽象 | `NewLife.Data.IPacket` / `ArrayPacket` | 支持链式内存段，避免大块内存复制 |
| IoT 驱动接口 | `NewLife.IoT.Drivers.DriverBase` | 标准化驱动接口，支持 IoTEdge 插件化加载 |
| 序列化 | `NewLife.Serialization.Binary`（大端模式） | 支持 `IsLittleEndian=false` 直接读写 S7 大端格式 |
| 日志 | `NewLife.Log.ILog` / `XTrace` | NewLife 统一日志门面，支持多种输出目标 |
| 多框架 | `<TargetFrameworks>net45;net461;netstandard2.0;netstandard2.1</TargetFrameworks>` | 覆盖老旧工控系统（.NET Framework 4.5）到现代 .NET |

## 6. 关键设计决策

### 6.1 单 TCP 连接模型

| 决策点 | 选择方案 | 备选 | 选择理由 |
|--------|---------|------|---------|
| 连接管理 | 单一 TCP 连接，串行化请求 | 连接池 / 多路复用 | S7 协议不支持请求 ID 复用同一连接；多连接会导致 PLC 资源耗尽 |
| 驱动共享 | 多个节点（INode）共享一个 S7Client | 每节点独立连接 | 减少 PLC 侧连接数量，PLC 通常有最大连接数限制 |

### 6.2 PDU 分段策略

```
ReadBytes(address, count):
    while count > 0:
        toRead = min(count, MaxPDUSize - 18)  // 18字节协议开销
        发送 ReadRequest(address, toRead)
        count -= toRead; address.StartByte += toRead

WriteBytes(address, value):
    while remaining > 0:
        toWrite = min(remaining, MaxPDUSize - 28)  // 28字节协议开销
        发送 WriteRequest(address, data[offset..offset+toWrite])
        remaining -= toWrite; offset += toWrite
```

### 6.3 字节序处理

- S7 协议全局使用**大端字节序**（`IsLittleEndian = false`）
- `SpanReader` / `Binary` 序列化器均以 `IsLittleEndian = false` 初始化
- Sequence 字段例外：小端存储（历史遗留，与 Wire 格式保持一致）
- 上层驱动（SiemensS7Driver.Read）调用 `data.Swap(true, true)` 处理非字符串类型的字节序

### 6.4 自动断线重连

```csharp
private async Task<Stream> GetStream(CancellationToken ct)
{
    if (_stream != null && _client != null && _client.Connected)
        return _stream;

    await OpenAsync(ct);  // 自动重建连接
    return _stream!;
}
```
每次 ReadBytes / WriteBytes 调用时通过 GetStream 隐式检测并重连，对上层透明。

### 6.5 S7-1200/1500 特殊要求

S7-1200/1500 使用扩展 S7 协议，默认仅允许 HMI 访问（基础读写）。需要在 TIA Portal 中：
1. 关闭 DB 的"优化块访问"（Optimized block access）
2. CPU 保护设置中选择"完全访问"并勾选"允许 PUT/GET"

## 7. 模块扩展方案（全部已完成）

### 7.1 F007 - 字符串地址类型化读写（✅ 已完成）

**实现文件**：`Protocols/S7Client.HighLevel.cs`

**实现思路**：
```
Read<T>("DB1.DBW0")
    → PLCAddress.Parse("DB1.DBW0") → address
    → ReadBytes(address, sizeof(T))
    → 字节序转换（大端 → 小端）
    → BitConverter / MemoryMarshal 转换为 T
    → return T
```

字节序转换工具：
- 整数类型（Word/DWord/Int/DInt）：直接 `BitConverter.ToXxx(buf.Reverse()...)`
- 浮点类型（Real/LReal）：先反转字节再 `BitConverter.ToSingle`
- 字符串（String）：跳过前2字节（最大长度+实际长度），读取 `buf[2..actualLen+2]`

### 7.2 F008 - 批量多变量读写（✅ 已完成）

**实现文件**：`Protocols/S7Client.Batch.cs`

**关键实现**：
1. 按 PDU 大小限制计算单次可打包的 RequestItem 数量
2. 超出限制时拆分为多个批次，结果合并后按原序返回
3. 批量写入同理，但 WriteRequest 同时包含 RequestItem 列表和 DataItem 列表

**DataItem 模型扩展**（参考 S7NetPlus 接口）：
```csharp
public class DataItem
{
    DataType DataType { get; set; }
    VarType VarType { get; set; }
    Int32 DB { get; set; }
    Int32 StartByteAdr { get; set; }
    Int32 BitAdr { get; set; }
    Int32 Count { get; set; }
    Object? Value { get; set; }   // 读取结果 / 写入值
}
```

### 7.3 F009 - S7Server PLC 模拟器（✅ 已完成）

**实现文件**：`Protocols/S7Server.cs`
- TCP 侦听（端口 102），基于 `NewLife.Net.NetServer<S7Session>`
- COTP CR 握手：回复 CC；S7 Setup 回显协商 PDU 大小
- 内置全区域内存存储（DB / M / I / Q / T / C），每区域 64KB 字节数组
- `GetMemory(DataType area, Int32 dbNum)` 统一访问各区域缓冲区
- `SetValue(string address, byte[])` 便捷预置测试数据接口
- ReadVar / WriteVar 完整处理，从内存区域读取/写入真实数据

### 7.4 F010 - SZL 诊断读取（✅ 已完成）

**实现文件**：`Protocols/S7Client.UserData.cs`，`Protocols/S7CpuInfo.cs`

使用 `S7Kinds.UserData` 消息类型，功能组 0x04（CPU 功能）。

关键 SZL ID：
- `0x001C`：CPU 识别信息（型号、序列号、固件版本）
- `0x0111`：CPU 模块信息
- `0x0131`：通信状态

**已提供 API**：
```csharp
// 读取 SZL 原始字节
Byte[] raw = await client.ReadSzlAsync(0x001C, 0x0000);

// 读取结构化 CPU 信息
S7CpuInfo info = await client.ReadCpuInfoAsync();

// 读取 CPU 运行状态（Run/Stop/Halt）
S7CpuStatus status = await client.ReadCpuStatusAsync();
```

### 7.5 F011 - PLC 时钟读写（✅ 已完成）

**实现文件**：`Protocols/S7Client.UserData.cs`，`Protocols/S7DateTimeHelper.cs`

使用 `S7Kinds.UserData` 消息类型，功能组 0x07（时钟功能）。

S7 DATE_AND_TIME 格式（8 字节 BCD 编码）：
```
Year(1) Month(1) Day(1) Hour(1) Minute(1) Second(1) MS_hi(1) MS_lo+DayOfWeek(1)
所有字段均为BCD编码，例如 2026年 → 0x26
```

**已提供 API**：
```csharp
DateTime plcTime = await client.ReadClockAsync();
await client.WriteClockAsync(DateTime.Now);
```

## 9. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 不同型号 PLC 的协议细节差异 | 高：可能导致读写失败 | 单元测试覆盖各 CPU 类型的 TSAP 计算；保留真机测试记录 |
| S7-1200/1500 PUT/GET 权限未开启 | 高：连接建立后读写失败 | 文档明确说明 TIA Portal 配置步骤；错误信息指向配置问题 |
| PDU 大小协商失败 | 中：分段逻辑可能不正确 | SetupMessage 协商失败时使用安全默认值（240 字节）；日志记录协商结果 |
| 长时间连接的心跳失效 | 中：连接静默断开不被检测 | TCP KeepAlive（15s 探测）+ 操作前 `client.Connected` 检查 + 异常时自动重连 |
| S7Plus 协议误用（1200/1500 新固件） | 低：连接直接被拒绝 | 文档明确标注，错误信息提示协议版本；不支持 S7Plus，建议用其他库 |
| 并发访问单一连接 | 中：读写交叉导致响应混乱 | 当前实现为串行调用；如需并发，上层需加锁（SiemensS7Driver 已通过单线程调用方式使用） |
